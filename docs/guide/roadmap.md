# 版本与路线图

> 路线图来自方案的 v0.3 稿（D01–D19 已定）。本页把“当前状态”和“计划”分开写，
> 以免把规划当成已交付。能力的逐项状态见 [实现状态](/guide/status)。

## 现在（M0 骨架）

- 仓库重建完成，六个服务可启动，CI 通过 `dotnet build` / `dotnet test` / `dotnet format` / `buf lint`。
- identity 的法人 / 网络账户领域模型与首个 EF 迁移落地。
- 开发用 Compose、Helm Chart 与文档站（本页所在站点）。
- SDK 三门客户端与 Admin 前端已开始落地（`sdk/`、`apps/admin`），但管理 API / console-api
  尚未实现，SDK 也还没有发布包。
- **还没有**登录页、OIDC、管理 API、会话、RBAC 与目录服务。

## v1.0（规划中）

| 里程碑 | 目标交付 | 出口标准（摘自方案） |
| --- | --- | --- |
| M0 骨架 | 六个服务 + 契约 + Compose + 登录/登出/令牌 + 账户 CRUD + Admin 骨架 + CI | Compose 起全套，curl 走完 PKCE；契约门禁生效 |
| M1 身份模型 | 法人/账户双层、账户切换、MFA、会话管理、审计、应用目录 | 一个实名实体绑定 3 个账户并切换；审计链可校验 |
| M2 授权 | 角色/权限/属性条件、决策 API、版本失效、组织与成员、邀请 | 越权用例全部拒绝；决策 P95 < 5 ms（命中缓存） |
| M3 SDK 与交付 | .NET / TS / Python SDK、3 个 sample、文档站、Helm chart | 外部团队按文档 30 分钟内接入 |
| M4 加固 | 压测、渗透测试、分片就绪验证、升级夹具、备份恢复演练 | 无高危漏洞；升级与回滚演练通过 |

::: warning 这些是计划，不是现状
v1.0 尚未发布。本仓库当前没有登录、令牌或管理 API 的可运行实现；上表用于说明
交付顺序，不能作为排期承诺。
:::

## v1.1（规划中，当前不可用）

以下能力**明确属于 v1.1**。文档中提到时会标为 🔭，请勿按已实现集成：

| 能力 | 说明 |
| --- | --- |
| Java / Go / PHP SDK | 三门首发 SDK 跑一个季度、facade 语义稳定后再复制 |
| 多分片启用与再平衡 | v1 只有逻辑分片层 + 单物理分片 |
| 外挂 PDP 连接器 | OpenFGA / SpiceDB；v1 内置 RBAC + 属性条件 |
| `Compliance.CN` 通道适配与日志归档 | v1 只交 Provider 契约、实名状态机与审计留存接口 |
| 上游 SAML（SP）、企业微信 / 钉钉 | v1 只覆盖 OIDC / LDAP 上游联邦 |

## 版本承诺（自 v1.0 起）

| 项 | 承诺 |
| --- | --- |
| API | `/api/v1` 保持 12 个月兼容；破坏性变更走 `/v2` |
| 数据库 | 每服务独立迁移，支持 N-1 小版本直接升级；迁移遵循 expand / contract |
| 安全 | 回补最近 2 个小版本 |
| SDK | `sdks/compat.md` 维护支持矩阵；SDK major ↔ API major |
| 发布 | 每月一个 minor；安全修复随时 patch |
