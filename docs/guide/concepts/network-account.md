# 网络账户（NetworkAccount）

> **状态**：领域模型与 EF 持久化 ✅ 已实现；登录、凭据校验与管理 API 🧭 v1.0 计划。

## 定位

网络账户是**登录身份**，不是“人”。一个人（法律实体）可以在公司、学校、客户门户
各有一个账户；这些账户可以属于不同 realm，但都挂在同一个法律实体下。

| 账户类型 | 是否绑定法律实体 | 用途 |
| --- | --- | --- |
| `Personal` | 必须 | 自然人使用的主账户 |
| `Service` | 禁止 | 机器 / 服务账户，不伪造法人 |
| `Managed` | 必须 | 由组织代管的账户（如员工入职批量创建） |

## 字段（已落地的模型）

| 字段 | 说明 |
| --- | --- |
| `Id` | UUIDv7 |
| `LegalEntityId` | 归属实体；仅 `Service` 可为空 |
| `Realm` | 品牌 / 产品域，小写，≤ 64 字符 |
| `Username` | 登录名，≤ 64 字符，realm 内唯一 |
| `Email` / `PhoneNumber` | 可空；分别有唯一索引 |
| `DisplayName` | 展示名，可空 |
| `Type` | `Personal` / `Service` / `Managed` |
| `Status` | `Active` / `Locked` / `Disabled` |
| `IsPrimary` | 是否主账户；只有 `Personal` 可以标记 |
| `CreatedAt` / `UpdatedAt` / `DisabledAt` | UTC 时间 |
| `xmin` | 并发令牌 |

## 生命周期

```text
Active ──Lock──▶ Locked ──Unlock──▶ Active
   │                │
   └────Disable─────┴────▶ Disabled（终态）
```

- `Lock` 只允许从 `Active`；
- `Unlock` 只允许从 `Locked`；
- `Disable` 可从 `Active` 或 `Locked`，之后不可恢复；
- `MarkPrimary` 只允许 `Personal`，且是单向操作。

## 不变量

| 编号 | 规则 | 落地方式 |
| --- | --- | --- |
| I2 | 一个账户只属于一个实体 | 单个 `LegalEntityId` 字段 |
| I3 | 一个实体可以有任意多个账户，可跨 realm | 无“每实体唯一账户”约束 |
| I4 | 登录标识在 **realm 内**唯一，不要求跨 realm 唯一 | `(Realm, Username)` 唯一索引 |
| I5 | 服务账户不绑定实体 | 创建时校验 |
| I6 | 实体停用 → 其所有账户会话立即失效，数据保留 | 目标能力；会话服务尚未实现 |

::: note 当前唯一索引的范围
代码里 `Email` 与 `PhoneNumber` 各自是全局唯一索引，而方案文字强调
“登录标识在 realm 内唯一”。两者并不矛盾：用户名按 realm 唯一，邮箱 / 手机号
作为可达标识目前按全局唯一处理。若后续要支持跨品牌复用同一邮箱，需要新的迁移，
属于契约演进，不能在 v1 内静默改变。
:::

## Realm

realm 是品牌 / 产品域的隔离边界：

- 用户名只在 realm 内唯一，避免不同品牌互相抢注；
- 同一实体在不同 realm 可以有不同账户；
- realm 会进入令牌 claim，资源服务用它做租户隔离。

## 当前可用性

目前没有创建 / 查询账户的 HTTP 端点；模型与迁移存在，服务启动后只暴露健康检查与
`/api/v1/meta`。不要基于它编写生产集成。
