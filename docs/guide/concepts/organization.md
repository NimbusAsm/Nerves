# 组织与成员

> **状态**：🧭 v1.0 计划。当前仓库的 directory 服务只有空壳，
> **没有组织表、成员 API、邀请流程或 SCIM 实现**。

## 组织是什么

组织（Organization）属于 **directory 服务**，表示单位、租户、部门或项目空间。
它与法律实体的区别：

| 概念 | 回答的问题 | 归属 |
| --- | --- | --- |
| 法律实体 | “这个实名主体是谁？” | identity |
| 网络账户 | “用什么身份登录？” | identity |
| 组织 | “账户在哪个单位 / 空间里、担任什么角色？” | directory |
| 角色 / 权限 | “能对什么资源做什么？” | authorization |

组织不是法律实体：一个法律实体可以是多个组织的成员；一个组织也可以包含多个
法律实体名下的账户。组织成员关系绑定的是**网络账户**，不是实名信息。

## 目标能力（v1.0 规划）

| 能力 | 说明 |
| --- | --- |
| 组织 CRUD | 创建 / 重命名 / 归档组织；组织有稳定的 ID |
| 成员管理 | 添加 / 移除成员、设置成员角色、成员状态 |
| 组（Group） | 组织内的分组，用于批量授权 |
| 邀请 | 邀请链接 / 邮件邀请；接受后建立成员关系 |
| SCIM 2.0 | 从上游目录同步用户与组（方案排 v1.0） |
| 组织作用域角色 | 角色作用域为 `org`，只在该组织内生效 |

::: warning 不要按“已实现”设计
以上全部是规划。当前没有 directory 的数据库 schema、迁移或 HTTP / gRPC 实现。
字段与语义最终以 directory 服务契约为准，本文不提前固化字段名。
:::

## 与授权的关系

授权模型中的角色有三种作用域：

- `global`：全平台；
- `app`：某个应用；
- `org`：某个组织。

组织成员关系本身不直接等于权限；权限由角色 / 权限绑定与属性条件共同决定。
详见 [权限与授权](/guide/concepts/authorization)。

## 与法律实体的关系

- 组织可以有关联的“法人”信息，但这是 directory 侧的引用，不是 identity 的外键；
- 服务之间只通过 ID 软引用，禁止跨 schema 外键；
- 删除组织不应删除法律实体或网络账户。
